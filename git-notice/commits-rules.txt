# ============================================================
# ПРАВИЛА ОФОРМЛЕНИЯ КОММИТОВ
# ============================================================
#
# 1. Общий формат
#
#    <тип>(<область>): <краткое описание>
#
#    <подробное описание (необязательно)>
#
#    <футер(ы) (необязательно)>
#
#    - тип — обязателен, одно слово в нижнем регистре
#    - область — необязательна, в скобках, указывает затронутый модуль
#    - краткое описание — обязательно, до 72 символов, без точки в конце,
#      в повелительном наклонении
#    - подробное описание — через пустую строку, объясняет что и почему,
#      а не как
#    - футеры — через пустую строку, например Closes #123,
#      BREAKING CHANGE: ...
#
# 2. Типы коммитов
#
#    feat      — новая функциональность
#    fix       — исправление бага
#    docs      — только документация (README, комментарии, Doxygen)
#    style     — форматирование, пробелы (без изменения логики)
#    refactor  — рефакторинг без изменения поведения
#    perf      — улучшение производительности
#    test      — добавление/изменение тестов
#    build     — система сборки, CMake, зависимости, vcpkg/conan
#    ci        — CI/CD конфигурации (GitHub Actions, GitLab CI)
#    chore     — прочие изменения (обновление .gitignore и т.п.)
#    revert    — откат предыдущего коммита
#
# 3. Примеры
#
#    feat(parser): добавить поддержку вложенных шаблонов
#
#    fix(network): устранить утечку сокета при таймауте
#
#    Сокет не закрывался при срабатывании таймаута подключения,
#    что приводило к исчерпанию файловых дескрипторов.
#
#    Closes #142
#
#    refactor(engine): вынести инициализацию рендерера в отдельный класс
#
#    build(cmake): повысить минимальную версию CMake до 3.20
#
#    docs(readme): добавить инструкцию по сборке под Windows
#
# 4. Правила написания
#
#    1) Повелительное наклонение: «добавить», «исправить», «удалить»,
#       а не «добавил», «добавлено».
#    2) Один коммит — одно логическое изменение. Не смешивать
#       рефакторинг и фичу.
#    3) Атомарность: после каждого коммита проект должен собираться
#       и проходить тесты.
#    4) Краткое описание ≤ 72 символов, тело — переносить по 72–80.
#    5) Без точки в конце краткого описания.
#    6) Язык: выбрать один — русский или английский — и придерживаться
#       его во всём репозитории.
#    7) Не коммитить сгенерированные файлы, артефакты сборки, секреты
#       (см. .gitignore выше).
#    8) Ссылки на задачи — в футере: Closes #123, Refs #456.
#    9) Breaking changes помечать явно:
#       feat(api)!: изменить сигнатуру create_widget()
#       или футером BREAKING CHANGE: описание.
#
# 5. Ветки
#
#    main / master     — стабильная ветка, только через PR/MR
#    feature/<кратко>  — новая функциональность
#    fix/<кратко>      — исправление
#    chore/<кратко>    — прочие изменения
#    docs/<кратко>     — документация
#    Имя ветки — в нижнем регистре, слова через дефис.
#
# 6. Проверка перед коммитом
#
#    git status              # убедиться, что в индекс попало нужное
#    git diff --cached       # просмотреть изменения
#    cmake --build build && ctest --test-dir build
#
# 7. Рекомендуемые инструменты (необязательно)
#
#    commitlint + husky — автоматическая проверка формата сообщений
#    clang-format       — единый стиль кода (pre-commit хук)
#    pre-commit         — запуск форматтеров/линтеров перед коммитом
